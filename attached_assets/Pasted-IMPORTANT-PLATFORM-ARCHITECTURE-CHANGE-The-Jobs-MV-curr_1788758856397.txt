IMPORTANT PLATFORM ARCHITECTURE CHANGE

The Jobs MV currently appears to have both:

1. Employer Workspace
2. Recruiter Workspace

This is confusing because both areas are designed for essentially the same type of user: companies and people hiring candidates.

I want to SIMPLIFY the platform.

There should be ONE unified hiring workspace:

EMPLOYER WORKSPACE

Do NOT maintain a separate Recruiter Workspace.

IMPORTANT:
Before changing anything, AUDIT the existing Employer Workspace and Recruiter Workspace.

Identify:
- Pages
- Routes
- Components
- Features
- Database relationships
- Authentication logic
- User roles
- Permissions
- Vacancy functionality
- Application functionality
- Candidate screening
- Shortlisting
- Interview functionality
- Company profile
- Recruitment requests
- Talent Search
- Any unique recruiter functionality

Do NOT simply delete the Recruiter Workspace.

Merge useful Recruiter Workspace functionality into Employer Workspace first.

Do not lose existing data or working functionality.

23. MIGRATION SAFETY
--------------------------------------------------

Before removing anything:

1. Audit Employer Workspace.

2. Audit Recruiter Workspace.

3. Compare features.

4. Identify duplicate features.

5. Identify unique Recruiter features.

6. Identify unique Employer features.

7. Define which existing component becomes canonical.

8. Merge missing functionality.

9. Map existing recruiter users to employer users.

10. Preserve data relationships.

11. Update navigation.

12. Update routes.

13. Add safe redirects.

14. Test authentication.

15. Test data.

16. Test permissions.

17. Only then remove obsolete duplicate UI/components.


Do not perform destructive database migration unless necessary.

Prefer backward-compatible migration.
